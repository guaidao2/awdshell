# awdshell

图形化的安全运维工作台。一个窗口里完成 SSH 连接、文件管理、数据库管理、资源监控、日志攻击检测与基线合规核查，交付形态是单个可执行文件。

面向日常单机安全运维：连上去、看状态、查配置、改数据、扫日志、出结论。

同时面向 AWD / AWDP 这类攻防演练中的**防御**工作。比赛里真正耗时间的是防守动作——按日志找出攻击载荷、清掉被传上来的 webshell、把被改坏的配置改回去、核对基线偏差、盯异常进程与外联端口；这些恰好是上面这组能力直接覆盖的事。它不做攻击侧的自动化：取 flag 那些动作大多不经过 SSH，也不是这个工具要解决的问题。

## 它解决什么

安全运维的日常大多在几个窗口之间来回切：SSH 客户端敲命令、SFTP 客户端传文件、另开页面看监控、再用命令行翻日志找异常。awdshell 把这些收进同一个界面，并且把「检测」做成一等功能——日志里的攻击载荷、主机上的配置偏差，直接在界面上给结论和整改建议。

## 功能

**SSH 终端**

- 多标签会话，单屏 / 左右 / 上下 / 四格分屏
- 每个目标独立的初始目录，目录不存在时自动回退到家目录
- 终端里 cd 之后，文件面板可以跟着跳过去
- 断线自动重连（服务端保留 30 秒宽限），连接状态在标签上直接可见

**文件管理（SFTP）**

- 浏览、上传、下载、改名、新建目录
- 内置编辑器，按扩展名做语法高亮；未保存的改动在关闭前会确认
- 权限列一眼可见，其他用户可写与带 SUID 的会标出来，也能直接改权限
- 删除默认移入远端回收站（`~/.awdshell-trash/`），可还原
- 下载目录可在设置里指定：文件下载与所有导出（核查报告、日志检测结果、威胁态势、数据表 CSV）都直接写到该目录，留空则交给浏览器。同名文件自动加序号，不覆盖已有的

**数据库管理（MySQL / MariaDB / PostgreSQL）**

- 通过目标机已有的 SSH 连接访问，不直连数据库、也不在目标机装客户端：数据库通常只监听 127.0.0.1，程序自己拨隧道过去
- 库 / 表 / 字段三层对象树
- 图形化操作：点表直接看数据，分页、点列头排序、条件筛选、导出 CSV；双击单元格改值，可新增行、按主键删行
- 没有主键的表自动只读——没法安全定位到具体哪一行，硬按条件删改太危险；这类表会提示改用 SQL 编辑器
- 可查看字段结构与建表语句，也能用表单建表（字段名、类型、非空、主键、自增、默认值）
- 内置 SQL 编辑器（Ctrl+Enter 执行），复杂查询走这里
- 会大范围改数据的语句（DROP / TRUNCATE / 没有 WHERE 的 DELETE 与 UPDATE）在执行前二次确认
- 连接可选「只读模式」，适合连生产库时防手滑；默认关闭
- 连接密码与 SSH 凭据走同一套加密落盘

**资源监控**

- 分核 CPU、内存明细、负载、磁盘、进程池（可按 CPU / 内存 / PID 排序与过滤）
- 网络速率与历史折线
- 网络连接与对端端口排行、监听端口列表（对外监听标出来），排查外联最直观

**日志攻击检测**

- 90 余条内置规则，覆盖 SQL 注入、XSS、命令注入、路径穿越、WebShell、扫描器探测、敏感文件、JNDI 注入、反序列化、认证爆破、提权与持久化、挖矿外联
- 按日志类型分流规则集：Web 访问日志不会去套系统日志的特征，反之亦然
- 约 20 种变形还原：URL 编码、SQL 十六进制、CSS 转义、Shell 引号与转义、变量展开、Base64、注释替换等；原文看不出、解码后才命中的会单独标记
- 跨行关联分析：多次失败后登录成功、账号扫描、撞库、分布式爆破
- 结果可导出 CSV，命中片段与关联结论都在里面

**基线合规核查**

- 60 余条检查项，覆盖身份鉴别、访问控制、SUID 提权面、安全审计、入侵防范、系统加固、常见提权路径
- 依据 GB/T 22239-2019（等保 2.0）三级要求与 CIS 公开加固要求
- 每项给出结论、说明、整改建议，以及实际执行过的命令（便于手工复核）
- 报告落库可回看，也能导出成一份自包含的 HTML 报告；历史记录可逐条删除或按主机清空（后台另按保留期自动清理）
- 长任务可取消

**威胁态势**

- 攻击来源排行、时间线、攻击类型与目标分布、命中规则排行、最近事件
- 数据跨扫描次数、跨目标累计；可只看全部主机或某一台
- 可导出 CSV

**界面与偏好**

- 深色界面，等宽读数，整页视图之间严格互斥
- 分屏模式、面板宽度、目录跟随等偏好保存在本地，重启后保持

## 安全设计

- **控制面只服务本机**：HTTP 接口监听 127.0.0.1 的随机端口
- **控制面令牌**：每次启动生成随机令牌并注入页面，前端请求自动携带。令牌覆盖**全部** `/api/` 接口，包括读接口——不以请求方法、本机来源或 Host/Origin 作为放行依据；静态资源与令牌注入脚本本身不要求令牌，否则页面拿不到令牌
- **主机密钥校验**：首次连接记录指纹，之后指纹不一致直接拒绝并说明原因，避免中间人无感接管
- **凭据加密落盘**：密码与私钥用 XChaCha20-Poly1305 加密，密钥文件与数据库分离存放
- **破坏性操作可回滚**：删除默认进远端回收站；不可逆操作在执行前二次确认并写明是哪台主机
- **检测只读**：日志检测与基线核查只读取目标机信息，不修改配置
- **数据库只读可选**：开启后由数据库自己在服务端拒绝写操作（不是靠客户端正则过滤）

## 下载

到 [Releases](https://github.com/guaidao2/awdshell/releases) 下载 `awdshell-windows-amd64-v1.1.1.zip`，解压后双击 `awdshell.exe`。

Windows 上依赖系统自带的 WebView2（Windows 11 与较新的 Windows 10 已预装）。

## 从源码构建

需要 Go 1.27 或更新版本，以及 [Wails CLI](https://wails.io)：

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@latest
git clone https://github.com/guaidao2/awdshell.git
cd awdshell
wails build -trimpath -ldflags "-s -w"
```

产物在 `build/bin/awdshell.exe`。

前端是 `frontend/dist` 下的免构建静态资源（原生 JavaScript，内嵌 xterm.js 与 CodeMirror），不需要 Node 或 npm：构建链只有 Go 与 Wails CLI。

命令行参数：

- `-web`：不开窗口，起本地服务供浏览器访问
- `-data <目录>`：指定数据目录（默认 `%APPDATA%\awdshell`）
- `-open=false`：`-web` 模式下不自动打开浏览器

## 检测规则的维护方式

日志检测规则与基线检查项都以 YAML 描述，位于 `internal/infra/logscan/rules/` 与 `internal/infra/compliance/checks/`。新增一条规则或检查项不需要改 Go 代码，标准变更时只改 YAML。
